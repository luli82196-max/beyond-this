# Phase 12R — Portfolio Rebuild v0.1

Status: **DESIGN COMPLETE / PROJECT PRODUCTION NOT STARTED**  
Date: 2026-08-23  
Supersedes: **Phase 12.1: Real Content Inventory and Editorial Curation v0.1** as the next content route  
Scope: five core projects, capability coverage, production scale, cross-medium editorial placement, and priority  
Out of scope: project production, five-act production code, sound integration, Blender tree work, and content runtime implementation

## 0. Decision

Beyond This is the master work, not a container for a conventional Works list. The previous body of work becomes a source and experience library: it may contribute a shot, observation, technique, or lesson, but prior existence alone is not a reason to publish it.

Phase 12R selects **five** projects. Each begins with a creative problem and produces evidence across disciplines. A project is stored once; Book, Projection, and Interface receive different fragments, never three abbreviated copies of the same case study.

The final set is:

1. `BT-P01` — **The Distance Between / 之间的距离**: cinematic storytelling.
2. `BT-P02` — **One Memory, Many Frames / 同一段记忆**: controlled AI filmmaking.
3. `BT-P03` — **A Film That Does Not Exist / 一部不存在的电影**: a visual identity that moves; Visual Identity and Motion Design are merged.
4. `BT-P04` — **From Failure to Method / 从失败到方法**: one bounded creative workflow investigation.
5. `BT-P05` — **Beyond This / 不止于此**: the integrated interactive experience and the system that relates the other four.

This is a production slate, not a public navigation list. Public presentation remains the Room constellation defined in Phase 12.

## 1. Selection rules

- Begin with a question that remains meaningful when tool names are removed.
- Require one primary capability claim and no more than four secondary claims.
- Define an MVP that can stand as finished work, not a broken fraction of the ideal version.
- Give every fragment one primary medium and one editorial purpose.
- Publish process only when it demonstrates a decision, changed understanding, or transferable method.
- Reuse a shared fictional-film premise where useful, but do not force all projects into one fictional universe.
- Treat user availability, rights, credits, captions, source ownership, and mobile fallback as production gates.

## 2. Recommended project slate

### BT-P01 — The Distance Between / 之间的距离

- **Core question:** How can distance between one person and an ordinary space change meaning without exposition?
- **Primary capabilities:** directing, shot design, blocking, editing, sound-led narrative.
- **Secondary capabilities:** cinematography, performance direction, production design, restrained compositing.
- **Final form:** a 60–90 second live-action or lightly hybrid narrative film; one performer, one controllable location, minimal or no dialogue.
- **MVP:** 45–60 seconds, 6–10 planned shots, one performer, one location, available light plus one controllable source, complete edit and deliberate sound plan.
- **Ideal version:** 75–90 seconds, polished grade and mix, captions, poster still, annotated shot plan, and one alternate edit comparison.
- **Difficulty:** medium.
- **Tools/media:** camera or capable phone, lighting, location sound/foley, NLE, optional AE cleanup.
- **Main risks:** vague premise, dependence on actor/location availability, weak recorded sound, overshooting, and mistaking mood for narrative change.
- **User-owned work:** select premise/location/performer; direct and shoot; approve performance, edit, and final emotional rhythm; secure releases.
- **Codex/AI/Blender contribution:** premise constraints, beat sheet, shot-list alternatives, schedule, continuity checklist, edit review rubric, captions and delivery manifest. No Blender dependency.
- **Book:** one spread pairing the spatial premise, a blocking diagram, and the observation that changed the shot plan.
- **Projection:** owns the finished film; ambient 6–10 second reversible fragment, then the requested complete film.
- **Interface:** one edit or sound comparison showing how a specific decision changed meaning.
- **Why it belongs:** it anchors the portfolio in human judgment, physical reality, and temporal control; it prevents the whole work from reading as an AI/technical demonstration.
- **Recommendation:** **yes**.

### BT-P02 — One Memory, Many Frames / 同一段记忆

- **Core question:** Can a remembered event remain visually and emotionally coherent when every image must be synthesized and controlled?
- **Primary capabilities:** AI filmmaking direction, visual development, character/scene continuity, storyboard-to-shot control, editing and finishing.
- **Secondary capabilities:** writing, compositing, color, sound conception, production pipeline design.
- **Final form:** a 45–75 second AI or hybrid moving-image piece built around one character, one recurring place, and one recurring object.
- **MVP:** 30–45 seconds, 5–7 shots, one character anchor sheet, one location anchor sheet, storyboard, consistency log, final edit, and poster fallback.
- **Ideal version:** 60–75 seconds, 8–12 shots, controlled camera/motion language, selective image-to-video, cleanup, grade, captions, credits/disclosures, and a concise making-of trace.
- **Difficulty:** high.
- **Tools/media:** image and video generation tools selected after tests, compositing/NLE, optional practical textures or plates; tool choice remains metadata rather than the concept.
- **Main risks:** identity drift, style drift, uncontrolled generation cost, rights/provenance ambiguity, endless regeneration, and a demo-reel structure with no dramatic turn.
- **User-owned work:** define memory/emotional premise; select and reject generations; make final directing judgments; edit or supervise edit; verify source rights and disclosures.
- **Codex/AI/Blender contribution:** visual bible schema, prompt/test matrix, shot dependency plan, consistency scoring, provenance log, batch naming, review board, and editorial synthesis. Blender may supply only simple spatial blocking/reference if it materially improves shot consistency.
- **Book:** visual bible fragment: character/place/object anchors plus a short note about what must remain stable and what may change.
- **Projection:** owns the final moving-image work and one calm ambient fragment.
- **Interface:** two or three consequential iterations, including a failure, the diagnosis, and the changed constraint.
- **Why it belongs:** it proves control of AI inside a directed pipeline rather than mere access to generation.
- **Recommendation:** **yes**.

### BT-P03 — A Film That Does Not Exist / 一部不存在的电影

- **Core question:** How can one visual grammar make an unseen film feel culturally and emotionally real across static and moving encounters?
- **Primary capabilities:** visual identity, typography, layout, color system, motion language.
- **Secondary capabilities:** film positioning, art direction, title design, compositing, editorial consistency.
- **Final form:** one compact identity system for a fictional film: key poster, title lockup/type treatment, two supporting formats, and a 12–20 second title/motion piece.
- **MVP:** one-page premise; type, color and image rules; one key poster; one alternate crop; one 8–12 second title sting using the same rules.
- **Ideal version:** key art, title system, 2–3 social/editorial formats, 15–20 second opening-title excerpt, style frames, usage sheet, and one rejected-route comparison.
- **Difficulty:** medium.
- **Tools/media:** layout/vector/raster tools, typography, AE or equivalent motion/compositing, optional generated or photographed source image with documented rights.
- **Main risks:** designing too many collateral pieces, substituting polish for a clear premise, type licensing, inconsistent motion bolted onto a static system, and overlap with BT-P02.
- **User-owned work:** choose the fictional-film premise; make art-direction and typography judgments; select/licence type and imagery; approve final system and motion rhythm.
- **Codex/AI/Blender contribution:** brief and constraint matrix, naming/copy options, layout/motion test plan, consistency audit, deliverable specs. Blender is unnecessary unless one simple object/render is the identity's owned source image.
- **Book:** owns the static system: premise, key poster crop, type/color rules, and one explanation of a compositional decision.
- **Projection:** owns the motion/title outcome, not a slideshow of collateral.
- **Interface:** one rejected direction → diagnosis → revised rule comparison.
- **Why it belongs:** it demonstrates that a visual idea can become a repeatable system and remain coherent in time, covering graphic and motion capability with one controlled workload.
- **Recommendation:** **yes**.

### BT-P04 — From Failure to Method / 从失败到方法

- **Core question:** How does a failed attempt become a reusable creative decision method rather than discarded output?
- **Primary capabilities:** research, problem framing, experimentation, prompt/workflow design, critical iteration, reflection.
- **Secondary capabilities:** documentation, prototyping, evaluation design, automation, communication.
- **Final form:** a bounded investigation of one real production problem from BT-P01, P02, or P03, expressed as a 3–5 step evidence trail and a reusable decision framework.
- **MVP:** one problem statement, three meaningful attempts, explicit evaluation criteria, one failure analysis, one changed rule, and one validated final attempt.
- **Ideal version:** 4–6 attempts, versioned evidence, a compact decision tree or comparison tool, limitations, and proof that the method transferred once to another shot/layout.
- **Difficulty:** low to medium because it reuses active project evidence.
- **Tools/media:** the tools required by the selected problem, structured notes, screenshots/crops, lightweight diagram or micro-interaction.
- **Main risks:** becoming a prompt dump, choosing a trivial problem, presenting success-only hindsight, excessive technical detail, or duplicating BT-P02's entire process.
- **User-owned work:** nominate a genuinely difficult decision; preserve failures; state evaluation criteria and final judgment; confirm what was learned rather than retrofitting a story.
- **Codex/AI/Blender contribution:** experiment design, version log, comparison normalization, failure taxonomy, decision-tree drafting, concise editorial copy, and optional lightweight prototype. Blender only if the chosen test is spatial/3D.
- **Book:** the originating question and the observation that reframed it; no tutorial.
- **Projection:** normally only a very short before/after motion result; no separate full film. It may be omitted if movement adds no evidence.
- **Interface:** owns the 3–5 step investigation, comparison, and transferable method.
- **Why it belongs:** it reveals the maker's reasoning under uncertainty—the capability least visible in polished finals—and gives Interface an authentic purpose.
- **Recommendation:** **yes**, but derive it from another project's real obstacle rather than inventing a standalone exercise.

### BT-P05 — Beyond This / 不止于此

- **Core question:** Can a portfolio become an authored journey in which nature, making, tools, and lived meaning are understood through relation rather than categories?
- **Primary capabilities:** experience direction, interaction design, 3D/WebGL, front-end systems, art direction, cross-disciplinary integration.
- **Secondary capabilities:** narrative architecture, accessibility, performance/loading design, editorial systems, production planning.
- **Final form:** the complete five-act Seed → Forest → Tree → Room → Light experience, with Room holding a constellation of traces and Light returning those traces to the world.
- **MVP:** the already established five-act experience plus a curated, non-duplicative Room content layer using posters/stills and bounded focus states; no requirement that every ideal deep state ship initially.
- **Ideal version:** production-quality assets, complete Book/Projection/Interface focus and selected deep states, robust mobile/reduced-motion/accessibility paths, measured loading budgets, and an authored case-study trace.
- **Difficulty:** high; it is the master work and should grow incrementally.
- **Tools/media:** React, TypeScript, Three.js/React Three Fiber, WebGL, Blender assets where separately approved, DOM accessibility layers, authored image/video content.
- **Main risks:** endless scope, self-congratulatory process display, performance and accessibility debt, duplicated case studies, and allowing the website project to consume the production of the other works.
- **User-owned work:** final proposition and taste decisions; approve narrative, art direction, pacing, and curation; supply/clear personal materials; evaluate the embodied experience.
- **Codex/AI/Blender contribution:** architecture and implementation support, content schema, performance/accessibility checks, editorial mapping, test plans, documentation; Blender supports approved spatial assets in a separate production line.
- **Book:** selected origin notes, relationships, and observations that shaped the five-act proposition—not a chronological development diary.
- **Projection:** at most one short authored capture or spatial fragment showing the experience as lived; not a promotional showreel of the site.
- **Interface:** one decisive system/problem trace such as persistent-canvas loading or content-state ownership; not a repository dashboard.
- **Why it belongs:** it is the integrating thesis. The other projects supply evidence; Beyond This authors the relationships between them.
- **Recommendation:** **yes**, as the master work rather than an equal fifth thumbnail.

## 4. Combination review

### 4.1 Repetition

- BT-P01 and BT-P02 both use directing/editing, but their proof differs: physical performance and location control versus synthetic consistency and pipeline control.
- BT-P02 and BT-P04 share iteration evidence. The boundary is strict: P02 owns the film and only a few consistency decisions; P04 owns one transferable method extracted from a real obstacle.
- Standalone Visual Identity and Motion Design would repeat art direction, typography, compositing, rhythm, and Projection space. Keeping them separate would add deliverables more than capability coverage.
- BT-P05 overlaps every project by design, but it must show integration and experience authorship—not re-present their complete outcomes.

### 4.2 Missing capabilities

The five cover directing, cinematography judgment, editing, sound conception, AI control, visual systems, typography, motion, research/iteration, interaction, 3D, front-end, accessibility, and cross-disciplinary art direction. The most important underexposed capability is **collaboration/production leadership**. Do not add a sixth project solely for it; document credits, constraints, handoffs, releases, and decisions inside P01–P03. Writing is also present but secondary; concise premises, captions, and editorial text are sufficient for v0.1.

### 4.3 Merge decision

Merge candidate C (Visual Identity) and D (Motion Design) into BT-P03. Motion becomes the temporal behavior of the identity rather than a separate AE exercise. This saves concept development, source-asset production, and editorial space while producing stronger system evidence.

A secondary optional merge is BT-P04 into BT-P02 if real production evidence never yields a method transferable beyond that film. Do this only after P02 production: a weak standalone workflow project is worse than a strong Interface trace inside P02.

### 4.4 Five versus six

Recommend **five**. Six creates a separate Motion project with the highest overlap and raises completion risk. If BT-P04 fails its transfer test, ship four authored subprojects plus the master work rather than manufacturing a fifth exercise.

## 5. Production priority and concurrency

1. **BT-P03 — A Film That Does Not Exist.** Start first. It is controllable, medium-scale, quickly establishes a visual premise, and can produce Book, Projection, and Interface test fragments without a shoot or unstable long-form generation.
2. **BT-P01 — The Distance Between.** Begin premise/location planning in parallel with P03; shoot only after the shot and sound plan is locked.
3. **BT-P02 — One Memory, Many Frames.** Begin visual-bible and feasibility tests after P03 establishes an art-direction discipline; cap shots and generation rounds before production.
4. **BT-P04 — From Failure to Method.** Capture evidence from day one, but choose and author the final method only after P01–P03 generates a real consequential failure.
5. **BT-P05 — Beyond This.** Continue as the master editorial/technical frame after at least P03 reaches MVP. Do not expand production code during Phase 12R.

Safe parallel work:

- P03 system design can run alongside P01 premise, location, and casting preparation.
- P02 story/anchor bible can run alongside P01 post-production, but not alongside uncontrolled final generation.
- P04 evidence capture runs quietly across all work; its editorial assembly waits.
- P05 content mapping can use finished fragments, while feature implementation waits for real asset specifications.

## 6. Gates and definition of done

Every project must pass:

1. **Question gate:** the creative problem is understandable without software names.
2. **MVP gate:** the bounded version has a complete beginning, change, and resolution/system.
3. **Evidence gate:** primary capability is visible in decisions, not asserted in labels.
4. **Difference gate:** the project adds a proof not already carried more strongly by another.
5. **Rights gate:** sources, collaborators, type, music, likeness, AI provenance/disclosure, and publication status are recorded.
6. **Placement gate:** Book/Projection/Interface fragments have distinct jobs and one deep owner.
7. **Delivery gate:** captions/alt text, poster/mobile fallback, duration/aspect ratio, credits, and source locations are known.

## 7. Relationship to Phase 12 and prior work

Phase 12's content architecture remains valid: movements, relations, fragment ownership, interaction depth, loading constraints, rights gates, and the Book/Projection/Interface responsibilities are retained. What changes is the source of the content. Instead of inventorying 6–12 old works as the default next action, Phase 12R commissions a compact set of purpose-built works and treats old work as optional source material.

The former Phase 12.1 route is retained for history and marked superseded. Its inventory template remains useful later as an asset/rights intake checklist, but it is no longer the editorial selection strategy.
